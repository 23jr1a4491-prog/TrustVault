# Project Submission Form: TrustVault

## TrustVault — Secure sharing, Smarter Access, Verifiable Accountability

TrustVault is a secure, multi-tenant document-sharing platform that enables organizations to upload, share, and manage confidential documents through role-based access control and tamper-evident audit tracking.

---

## The problem

Organizations handle sensitive files—such as financial records, internal contracts, and personal data—that require rigorous access boundaries. Traditional file-sharing solutions often fail to enforce strict boundaries between administrative oversight, document ownership, and view-only rights. This creates serious vulnerabilities: unauthorized users may attempt to modify permissions, viewers might gain unintended administrative visibility, and tracking who accessed what becomes difficult.

TrustVault addresses this challenge by establishing a strict 3-tier user role architecture: **Admin**, **Owner**, and **Viewer**. Only document owners retain authority to grant or revoke access to their uploaded files, while system administrators maintain oversight of platform health and security metrics. If any unauthorized user attempts to alter permissions or access restricted logs, the system blocks the request and enforces clear security boundaries.

---

## What I built

TrustVault is a full-featured, secure document management web application built with a responsive Flask backend and a modern UI.

Key functional capabilities include:
- **Authentication & User Lifecycle**: Secure registration and login workflows with credential encryption, profile management, and password update mechanisms.
- **Role-Based Navigation & Access**: An intuitive navigation bar offering access to the Dashboard, My Documents, Search, Categories, Upload, and Activity Logs, dynamically tailored to user roles.
- **Admin Security Dashboard**: Administrators have exclusive access to high-level system telemetry—including total documents uploaded, registered users, active sharing relationships, and system health status.
- **Audit Logging**: Comprehensive tracking of user login and logout timestamps reserved exclusively for administrators to ensure end-to-end accountability.
- **My Documents & Management**: A central workspace where users review metadata for files they own and safely delete obsolete records.
- **Multi-Filter Document Search**: Fast, flexible search functionality allowing users to filter documents by upload date, category, file name, and owner.
- **Controlled Sharing & Permissions**: Document owners can upload files and explicitly assign viewing privileges to specific users, while preventing non-owners from tampering with access settings.

## How to run it

Follow these steps to run TrustVault locally:

```powershell
# 1. Navigate to the project root directory
cd <project-directory-path>

# 2. Activate the virtual environment
.\.venv\Scripts\Activate.ps1

# 3. Install project dependencies
python -m pip install -r requirements.txt

# 4. Start the application
python run.py

# 5. Run automated security & RBAC tests
python test_security.py
```

Then open your browser and navigate to:
```
http://127.0.0.1:5000/
```

*Prerequisites: Python 3.8+ and pip must be installed on your system.*

## What the AI got wrong, and what I fixed myself

During development, relying solely on AI outputs revealed several limitations that required manual intervention and debugging:
1. **Design System & Theme Mismatches**: When asked to implement a clean dashboard theme using black and emerald green, the AI generated uncoordinated styles featuring high-contrast neon yellow accents. I manually redesigned the CSS styles and components to achieve a professional, dark-themed UI with emerald green highlights.
2. **Architecture & File Redundancies**: The AI generated boilerplate containing unnecessary files and convoluted directory structures. I restructured the project tree to maintain a clean, maintainable Flask architecture.
3. **Permission Logic & Edge Cases**: The initial access-control code generated by the AI contained gaps where permission checks could be bypassed. I audited the permission verification logic to strictly ensure that only the document owner or admin can modify file sharing privileges.
4. **Prompt Engineering**: When generated code did not align with specific requirements, I iteratively refined prompts and applied manual debugging to ensure code reliability.

## What is not finished

All core features of TrustVault—user authentication, document upload and download, role-based sharing permissions, multi-filter search, and administrative audit logging—are fully implemented and operational on desktop browsers.

However, the following areas remain in progress for future iterations:
- **Mobile-Responsive UI**: While the desktop experience is polished, mobile screen layouts (such as compact navigation drawers and condensed data tables) need further optimization.
- **File Encryption at Rest**: Extending security to include AES-256 encryption for stored files on the server disk.
- **Time-Expiring Share Links**: Allowing document owners to share temporary access tokens with automatic expiration.
